# Embedding and Vector Storage - Complete Guide

## Overview

This guide covers the embedding generation and vector storage layer that transforms portfolio documents into searchable vectors stored in ChromaDB.

---

## Architecture

```
Portfolio Documents (Step 3)
        ↓
createPortfolioDocuments()
        ↓
For each document:
  ├─→ embeddingService.generateEmbedding(text)
  │   └─→ OpenAI API (text-embedding-3-small)
  │       └─→ 1536-dimensional vector
  │
  └─→ chromaService.upsertDocument({id, content, embedding, metadata})
      └─→ ChromaDB
          └─→ Stored with deterministic ID
```

---

## Services Created

### 1. **embeddingService.js**
Generates vector embeddings using OpenAI API.

**Key Methods:**
- `initialize()` - Initialize OpenAI client
- `isReady()` - Check if service is ready
- `generateEmbedding(text)` - Generate single embedding
- `generateEmbeddings(texts)` - Batch generate embeddings
- `getModelInfo()` - Get model details

**Model Used:**
- `text-embedding-3-small`
- 1536 dimensions
- Cost: $0.00002 per 1K tokens

### 2. **chromaService.js**
Manages vector storage in ChromaDB.

**Key Methods:**
- `initialize()` - Connect to ChromaDB and get/create collection
- `isReady()` - Check if service is ready
- `upsertDocument({id, content, embedding, metadata})` - Store/update single document
- `upsertDocuments(documents)` - Batch store/update documents
- `getDocument(id)` - Retrieve document by ID
- `getAllDocuments()` - Get all documents
- `count()` - Count documents
- `getStats()` - Get collection statistics
- `clearCollection()` - Delete all documents

**Upsert Behavior:**
- Uses deterministic IDs from Step 3
- Same ID = update existing vector
- New ID = add new vector
- Safe to run indexing multiple times

### 3. **portfolioIndexer.js**
Orchestrates the complete indexing pipeline.

**Key Functions:**
- `indexPortfolioDocuments()` - Full indexing pipeline
- `reindexPortfolio()` - Alias for re-indexing
- `getIndexingStatus()` - Get service status

**Pipeline Steps:**
1. Check services are ready
2. Generate portfolio documents
3. For each document:
   - Generate embedding
   - Prepare for batch storage
4. Batch upsert to ChromaDB
5. Verify storage

## ChromaDB Setup

### Option 1: Docker (Recommended)

```bash
docker run -p 8000:8000 chromadb/chroma
```

### Option 2: Docker Compose

Create `docker-compose.yml`:
```yaml

services:
  chromadb:
    image: chromadb/chroma:latest
    ports:
      - "8000:8000"
    volumes:
      - ./chroma_data:/chroma/chroma
    environment:
      - IS_PERSISTENT=TRUE
```

Run:
```bash
docker-compose up -d
```

### Option 3: Python

```bash
pip install chromadb
chroma run --path ./chroma_data --port 8000
```

## Document Structure in ChromaDB

Each vector stored has:

```javascript
{
  id: "project-6ab4a8ba2a299ed74043a24b",  // Deterministic ID from Step 3
  content: "Project: ShoeHub...",           // Full document text
  embedding: [0.1, 0.2, ..., 0.5],         // 1536-dimensional vector
  metadata: {
    type: "project",                        // Document type
    sourceId: "project-6ab4a8ba...",       // Original ID
    title: "ShoeHub",                       // Document title
    technologies: [...],                    // Project-specific metadata
    indexedAt: "2026-09-12T10:30:00.000Z"  // Indexing timestamp
  }
}
```

---

## Deterministic IDs

IDs are generated by Step 3 and preserved:

- `profile-main` - Profile document
- `edu-1`, `edu-2` - Education documents
- `project-{mongoId}` - Project documents
- `experience-{mongoId}` - Experience documents
- `skills-{category}` - Skill category documents
- `certification-{mongoId}` - Certification documents

**Benefits:**
- Same document always has same ID
- Re-indexing updates existing vectors
- No duplicates created

## Error Handling

### Embedding Generation Fails

If one document fails:
- Error is logged with document ID
- Other documents continue processing
- Failed document is NOT stored
- Statistics include failure details

Example:
```javascript
{
  totalDocuments: 17,
  indexed: 16,
  failed: 1,
  failures: [
    {
      documentId: "project-123",
      type: "project",
      error: "OpenAI API rate limit exceeded"
    }
  ]
}
```

### Service Not Ready

If embedding service or ChromaDB is not ready:
- Clear error message is shown
- Indexing stops immediately
- No partial data is stored

## Collection Metadata

```javascript
{
  name: "portfolio",
  metadata: {
    description: "Portfolio content embeddings for RAG chatbot",
    "hnsw:space": "cosine"  // Cosine similarity for text
  }
}
```

**Why cosine similarity?**
- Standard for text embeddings
- Measures semantic similarity (not distance)
- Range: -1 (opposite) to 1 (identical)

## Troubleshooting

### Error: "OPENAI_API_KEY not found"

**Solution:**
1. Get API key from https://platform.openai.com/api-keys
2. Add to `.env`:
   ```
   OPENAI_API_KEY=sk-...
   ```
3. Restart server

### Error: "ChromaDB not available"

**Solution:**
1. Start ChromaDB:
   ```bash
   docker run -p 8000:8000 chromadb/chroma
   ```
2. Verify port 8000 is not in use
3. Run test again

### Error: "OpenAI API quota exceeded"

**Solution:**
1. Check OpenAI account billing
2. Add payment method if needed
3. Verify usage limits

### Error: "MongoDB connection timeout"

**Solution:**
1. Start MongoDB:
   ```bash
   mongod
   ```
2. Verify MongoDB is running on port 27017
3. Run test again
